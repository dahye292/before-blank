# 비포블랭크(Before Blank) — 코드가 동작하는 방식

면접에서 "이 부분은 어떻게 만들었어요?"라는 질문에 답할 수 있도록, 핵심 흐름을 순서대로 정리했습니다.
함수 이름으로 적어 두었으니 `app.py`, `static/app.js`에서 검색해 보면서 읽으면 됩니다.

---

## 1. 전체 구조

```
브라우저 (static/index.html · app.js · style.css)
   │  fetch로 JSON 주고받기 (AI 답은 글자가 생기는 대로 스트리밍)
   ▼
Flask 서버 (app.py) ──── SQLite (data/thinkfirst.db)
   │
   ▼
Claude API (답변 생성, 마인드맵 정리)
```

- 화면은 페이지를 새로 불러오지 않고 주소의 `#` 뒷부분만 바꿔 화면을 그립니다(해시 라우팅).
- 서버는 데이터를 저장하고 AI를 부르는 일만 합니다. 화면 HTML은 브라우저의 JavaScript가 만듭니다.

---

## 2. 데이터 구조 (DB)

```
topics (주제)                       turns (대화 턴)
─────────────                       ────────────────
id                                  id
name        주제 이름 (중복 불가)    topic_id   → topics.id (주제를 지우면 함께 삭제)
is_starred  중요 표시 0/1           question   질문
status      in_progress / done      my_thought 내 생각 (AI 답 전에 적음, 수정 불가)
mindmap     마인드맵 JSON (저장본)   ai_answer  AI 답
created_at, updated_at              reflection 생각 메모 (수정 가능)
                                    created_at, updated_at
```

- **주제 1개 : 대화 턴 N개** 구조입니다.
- 생각 메모는 주제가 아니라 **턴마다** 저장됩니다(`turns.reflection`).
- 마인드맵은 주제마다 하나를 저장해 두고 재사용합니다(아래 4번).

**자동 이전 (`init_db`)**
이전 버전은 질문 하나가 기록 하나(`entries` 표)였습니다. 서버를 켤 때 `entries` 표가 있으면
- 각 기록을 `turns`로 복사하고,
- 주제 안의 기록이 모두 완료였으면 주제도 완료로 표시하고,
- 원래 표는 지우지 않고 `entries_legacy`로 이름만 바꿉니다(되돌릴 수 있게).
- 이미 옮긴 뒤에는 `entries` 표가 없으므로 두 번 실행해도 중복되지 않습니다.

---

## 3. "생각 먼저" 흐름 — 질문부터 AI 답까지

1. **입력창 (`renderComposer`)**: 질문을 적고 `다음`을 누르면 내 생각 칸이 나옵니다. 20자 미만이면 `AI 답 보기` 버튼이 꺼져 있습니다.
2. **턴 저장 (`create_turn`, `POST /api/topics/<id>/turns`)**: 서버도 20자 미만이면 거절합니다(화면만 막으면 우회할 수 있으므로 서버에서도 확인). 이때 주제 상태를 `in_progress`로 바꿉니다 → 완료된 주제에서 대화를 이어 가면 자동으로 진행중.
3. **AI 답 요청 (`answer`, `POST /api/turns/<id>/answer`)**
   - `history_messages`가 같은 주제의 **이전 질문과 AI 답**만 대화 기록으로 만듭니다.
   - **내 생각(`my_thought`)은 어디에도 넣지 않습니다.** 이것이 편향을 막는 핵심입니다.
   - Claude API를 스트리밍으로 불러 글자가 생기는 대로 브라우저에 보내고, 다 받으면 DB에 저장합니다.
4. **화면 표시 (`streamAnswer`)**: 브라우저가 스트림을 조금씩 읽어 마크다운으로 바꿔 보여 줍니다. 오류가 나면 `다시 시도` 버튼을 띄웁니다.

---

## 4. 마인드맵 만들기

**서버 (`mindmap`, `build_mindmap`, `clean_mindmap`)**
1. 주제에서 AI 답이 있는 턴만 모읍니다.
2. 저장된 마인드맵이 있고, 그때의 **턴 ID 목록(`signature`)이 지금과 같으면** 저장본을 그대로 돌려줍니다 → 탭을 열 때마다 API를 부르지 않음. 대화가 늘거나 지워지면 목록이 달라져 자동으로 다시 만듭니다.
3. 다시 만들 때는 모든 턴을 `<turn id="...">` 형태로 묶어 Claude에게 보내고, **구조화 출력(JSON 스키마)**으로 정해진 모양의 답을 받습니다.
   ```
   { "mine_only": [요점], "shared": [요점 + kind(same/similar)], "ai_only": [요점] }
   요점 = { label: 짧은 핵심어, detail: 한 문장, turn_ids: [근거 턴 ID] }
   ```
4. `clean_mindmap`이 **실제로 없는 턴 ID를 걸러 냅니다.** AI가 잘못된 ID를 줘도 화면이 깨지지 않게 하기 위함입니다.
5. 여기서는 내 생각과 AI 답을 **둘 다** 보냅니다. 비교가 목적이고, AI 답은 이미 만들어진 뒤라 편향 문제가 없습니다.

**화면 (`renderMapTab`, `drawMapLines`)**
- 세 칸(내 생각 / 겹치는 생각 / AI 생각)을 HTML로 그리고, 그 위에 SVG로 연결선을 그립니다.
- 선은 각 카드의 실제 위치(`getBoundingClientRect`)를 재서 그립니다. 창 크기가 바뀌면 `ResizeObserver`가 다시 그립니다.
- 겹치는 생각으로 가는 선은 칸 사이 빈 공간을 따라 내려가게 해서 카드를 가로지르지 않습니다.
- 요점을 누르면 주소를 `#/topic/1?turn=5`로 바꿔 대화 탭으로 이동하고, `jumpToTurn`이 그 턴으로 스크롤한 뒤 잠깐 강조합니다.
- 접기·골라 보기 설정(`loadMapView`, `saveMapView`)은 브라우저 `localStorage`에 주제별로 저장합니다. 저장이 막혀 있어도 기본값으로 동작합니다.

## 5. 화면 이동 (라우터)

`route()`가 주소의 `#` 뒷부분을 보고 화면을 고릅니다.

| 주소 | 화면 |
|---|---|
| `#/` | 주제 목록 (`viewHome`) |
| `#/new` | 새 주제 (`viewNewTopic`) |
| `#/topic/1` | 대화 탭 (`renderChatTab`) |
| `#/topic/1?turn=5` | 대화 탭 + 5번 턴으로 이동 |
| `#/topic/1/map` | 마인드맵 탭 (`renderMapTab`) |

## 6. 안전하게 만든 부분

- **화면에 글을 넣을 때 모두 `esc()`로 바꿔 넣습니다.** 사용자가 `<script>` 같은 글을 적어도 실행되지 않습니다. AI 답의 마크다운 변환도 먼저 이스케이프한 뒤에 합니다.
- **API 키는 `.env`에만 두고 `.gitignore`로 git에서 제외**합니다. 코드에는 키가 없습니다.
- 디버그 모드는 `FLASK_DEBUG=1`일 때만 켜집니다.

## 7. 예상 질문과 답

**Q. 왜 AI에게 내 생각을 안 보내요? 보내면 더 맞춤형 답이 나오지 않나요?**
맞춤형 답이 나오는 대신, AI가 내 생각에 동의하거나 맞춰 주는 방향으로 답하기 쉽습니다. 이 앱의 목적은 내 생각과 AI 생각을 **독립적으로** 비교하는 것이라, 일부러 분리했습니다. 비교 결과(마인드맵)를 만들 때만 둘을 함께 보냅니다.

**Q. 두 번째 질문부터는 AI가 이전 답을 보는데, 그럼 독립적이지 않은 것 아닌가요?**
대화 흐름을 이어 가려고 이전 **질문과 AI 답**은 보냅니다. 하지만 내 생각과 생각 메모는 계속 보내지 않으므로, AI가 내 의견에 끌려가지는 않습니다.

**Q. 마인드맵이 틀리면요?**
AI가 '겹친다'고 판단한 것이 실제와 다를 수 있습니다. 그래서 모든 요점에 근거 대화를 연결해, 눌러서 원문을 바로 확인할 수 있게 했습니다. 요점을 직접 고치는 기능은 다음 계획에 있습니다.

**Q. 왜 React 같은 프레임워크를 안 썼어요?**
화면이 세 종류로 단순하고, 빌드 과정 없이 바로 실행되는 것이 더 중요했습니다. 대신 화면 코드가 한 파일에 커져서, 규모가 커지면 나누거나 프레임워크로 옮길 계획입니다.

**Q. AI로 만들었다는데, 본인은 뭘 했나요?**
문제를 정하고, 기능과 화면 흐름을 기획하고, 결과를 확인하며 수정 방향을 정했습니다. 예를 들어 처음에는 질문 하나 단위였지만, 실제로 써 보니 고민이 이어진다는 걸 느껴 주제·대화 구조로 바꾸자고 결정했고, 마인드맵도 양쪽 연결형이 복잡해서 겹치는 생각을 가운데로 모으는 형태로 바꿨습니다.

## 8. 회원과 기록 분리 (v3)

- `users` 표: 이름, 이메일(중복 불가), 비밀번호 **해시**, 나이, 성별. 비밀번호 원문은 어디에도 저장하지 않습니다(`werkzeug.security`).
- 로그인하면 Flask 세션 쿠키에 사용자 ID만 넣습니다. 쿠키는 `SECRET_KEY`로 서명돼서 사용자가 고칠 수 없고, `HttpOnly`(자바스크립트로 못 읽음), `SameSite=Lax`(다른 사이트 요청에 안 붙음)입니다.
- **모든 주제·대화·마인드맵 API는 `own_topic`, `own_turn`으로 "로그인한 사람의 것인지"부터 확인**합니다. 남의 것이면 "없다"(404)고 답해서, 다른 사람 기록이 있는지조차 알 수 없게 했습니다.
- 데이터를 바꾸는 요청은 JSON만 받습니다(`protect_api`). 다른 사이트의 일반 폼은 JSON을 보낼 수 없어서, 몰래 보내는 요청(CSRF)이 막힙니다.
- 회원 기능 이전 DB: `topics`에 `user_id`를 붙이고, 주제 이름 중복 규칙을 "전체에서 하나" → "사람마다 하나"로 바꾸려고 표를 다시 만듭니다. 기존 기록은 **첫 가입자**에게 넘어갑니다.

## 9. 폴더 (v3.1)

- `folders` 표(사람별), `topics.folder_id`(비어 있으면 '폴더 없음'). 폴더를 지우면 주제는 지우지 않고 `folder_id`만 비웁니다.

## 10. 마인드맵 직접 수정과 애매한 요점 (v3.1)

- AI에게 받는 JSON에 `uncertain` 묶음을 추가했습니다. 겹치는지 확신이 없는 쌍(내 요점, AI 요점, 사용자에게 물을 질문)은 마인드맵에 바로 넣지 않고 여기에 담습니다.
- 화면에서 "같은/비슷한/다른 생각"을 고르면, 프론트엔드가 마인드맵을 고친 뒤 `PATCH /api/topics/<id>/mindmap`으로 저장합니다.
- 서버의 `validate_user_mindmap`이 모양·글자 수를 검사하고, 내 대화가 아닌 ID는 지웁니다.
- 고친 마인드맵에는 `edited: true`가 붙고, 대화가 늘어도 자동으로 덮어쓰지 않습니다(`stale: true`로 알려 주기만 함).

**Q. 왜 AI 판단을 그대로 쓰지 않고 사용자가 고치게 했나요?**
'같은 생각'인지는 결국 사용자가 판단할 문제이고, AI가 틀리면 마인드맵이 오히려 사용자의 생각을 왜곡합니다. 이 앱의 목적이 "내 생각을 지키는 것"이라, 최종 결정권을 사용자에게 두었습니다.

## 11. 첨부파일 (v3.2)

- `attachments` 표에 원래 파일 이름·형식·크기를 두고, 파일은 `data/uploads/`에 **무작위 이름**으로 저장합니다(원래 이름으로 경로를 조작하지 못하게).
- 올리기는 파일이라 JSON이 아니므로, 직접 만든 헤더 `X-BB-Upload: 1`이 있는 요청만 받습니다. 다른 사이트는 이 헤더를 붙여 보낼 수 없어서 CSRF 방어가 유지됩니다.
- AI 답을 요청할 때 `attachment_blocks`가 텍스트는 글(한국어 CSV를 위해 cp949도 시도), PDF는 문서 블록, 그림은 이미지 블록으로 바꿔 질문 앞에 붙입니다. **내 생각은 여전히 보내지 않습니다.**
- 마인드맵을 만들 때도 자료를 함께 보내고, 결과 JSON의 `materials`(자료마다 요약·핵심·내 생각과의 연결)로 받습니다. 첨부가 바뀌면 서명(`signature`)에 `a<id>`가 더해져 마인드맵을 다시 만듭니다.
- 내려받기는 내 파일만, 항상 '파일로 저장'(`as_attachment`) + `nosniff`로 보내서 브라우저가 파일을 웹페이지처럼 실행하지 않게 했습니다.
- 대화·주제·계정을 지우면 디스크의 파일도 함께 지웁니다.

## 12. 비밀번호 찾기 (v3.2)

- 재설정 링크의 토큰은 `secrets.token_urlsafe`로 만들고, DB에는 **SHA-256 해시만** 저장합니다. 30분 뒤 만료, 한 번 쓰면 무효, 새 링크를 받으면 예전 링크도 무효입니다.
- 가입되지 않은 이메일에도 같은 안내를 보여 줘서, 누가 가입했는지 알아낼 수 없게 했습니다. 15분에 3번까지만 요청할 수 있습니다.
